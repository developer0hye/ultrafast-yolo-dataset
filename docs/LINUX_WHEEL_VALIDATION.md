# Linux wheel validation

The local CPython 3.12 Linux x86-64 wheel installed in the RTX 3070 host's
separate CUDA environment passed all **157 tests** in 17.16 s. JUnit and the
source-fingerprint manifest are under `validation/cuda-*`. This validates the
installed wheel in that environment; most tests are CPU tests.

An archive audit then found six generated `.pyc` files in the wheel. Python had
regenerated some after installation, so an initial whole-package byte comparison
correctly failed. Runtime source/profile/native bytes did match the archive.
`bench/audit_wheel.py` now checks every wheel RECORD digest/size, duplicate and
unsafe archive paths, generated bytecode, and optionally installed runtime bytes.
Its default exit status rejects generated bytecode. The v1 rejection is retained
as `validation/cuda-dataset-wheel-audit-v1-rejected.json`.

The explicit `tool.maturin.exclude` patterns remove `__pycache__`, `.pyc` and
`.pyo` files, including when building from a copied directory without Git state.
This uses Maturin's documented [archive exclusion configuration](https://www.maturin.rs/config.html).
The fresh v2 build passed the archive audit and has exactly the same runtime
source/profile/native bytes as the previously tested CUDA installation:
`validation/cuda-dataset-wheel-audit-v2.json`.

The v2 wheel was additionally installed into a new standalone Linux environment
with NumPy 2.4.4 and Pillow 12.1.1, without Ultralytics or Torch. All four
Detect/Segment × content/metadata cold/warm cache cases passed the frozen label
oracle, including writable array bytes, diagnostics, counters and same-size
restored-mtime invalidation behavior. The final installed-byte and RECORD audit
was clean. Reports and the build/install log are named
`validation/dataset-wheel-linux-clean-v2*`.

The archive is still tagged `linux_x86_64`, not repaired manylinux. These checks
do not establish Windows, other Python versions, full third-party notices or
release readiness. The original v1 CUDA environment remains unchanged for its
ongoing GPU training trials; generated bytecode removal does not change the
verified runtime source or native implementation.
